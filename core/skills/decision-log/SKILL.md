# 决策记录（轻量 ADR）

## 何时记录

- 技术选型（框架、库、数据库、部署方式）
- 架构边界与接口契约
- 不可逆或高成本的决定
- 用户明确拍板的方向
- 推翻了之前的决定

琐碎改动不记。

## 格式

```markdown
### D-<序号> <标题>
- 日期：
- 状态：提议 / 已采纳 / 已废弃 / 被 D-xx 取代
- 背景：为什么要做这个决定
- 候选：A / B / C（各自一句话优缺点）
- 决定：选了什么
- 理由：对照约束的关键依据
- 影响：涉及的文件/模块/接口
- 复审条件：什么情况下需要重新评估
```

## 存放

- 单仓库：`docs/decisions.md`（不存在就创建）
- 跨会话：同步一份摘要到记忆文件「关键决策与依据」
- 只写结论与依据，不贴大段代码

## 检索

回顾时先读决策文件的标题列表，命中再读对应条目；不要重扫代码库推断历史决策。

## 纪律

- 一个决定一条，不合并。
- 被取代的决定保留并标状态，不删除——历史也是信息。
- 决策与实现不一致时，先更新决策记录，再修实现。
