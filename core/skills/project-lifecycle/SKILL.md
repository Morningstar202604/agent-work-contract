# 项目全周期管理

目标：把「一个模糊的大请求」变成「一串可验收的小切片」，并明确项目何时才算真正结束。

## 阶段与门禁

| 阶段 | 产出 | 门禁（不满足不进下一阶段） |
|---|---|---|
| 0 立项 | 目标、范围、非目标、约束、成功判据 | 能用一句话说清「做完是什么样」 |
| 1 拆解 | WBS + 依赖图 + 风险清单 | 每个任务 ≤ 半天；有明确验收标准 |
| 2 计划 | 切片顺序、并行面、里程碑 | 每片可独立运行/验收，不依赖未完成片 |
| 3 执行 | 逐片实现 + 验证 + 台账更新 | 每片跑过验证命令，结果贴出 |
| 4 收尾 | 全量验证、清理、文档同步、记忆沉淀 | 无临时文件、无未关进程、无未完成待办 |

## 切片原则

1. **垂直切片**：每片从入口到落地打通一条完整路径，而不是「先写完所有 model 再写所有 view」。
2. **可独立验收**：一片做完就能演示或跑测试，不依赖下一片。
3. **小**：单片改动控制在能一次说清的范围；超过就继续拆。
4. **有序**：先做被依赖的、风险最高的、能最早证伪假设的。
5. **可回滚**：每片一个提交（或一次可回退的改动集）。

## 阶段状态

项目状态写在记忆文件与运行态里，三档：

- `active`：正常推进。切片之间可以停，**不要求**关闭进程、不要求清空全部待办。
- `closing`：用户宣布收尾 / 计划全部完成 / 准备交付。此时才做全量收尾。
- `done`：收尾完成，台账归零。

切换方式：`node <规则目录>/hooks/ledger.js phase active|closing|done`

## 反模式

- 拿到需求直接写代码，没有拆解与验收标准。
- 一次改十几个文件、跨多个模块，出问题无法定位。
- 每轮结束都把服务关掉，下一轮重新起——浪费启动时间且丢失现场。
- 把「计划里还有下一片」误判成「项目没做完」，反复阻断收尾。

## 交付时给三张清单

1. 已完成：切片、对应验证命令与结果。
2. 未完成：剩余切片、原因、下一步。
3. 风险与假设：未验证的假设、已知坑、需要用户决策的点（自行按默认值处理并标注）。
