# 交付质量基线

## 五条硬要求

1. **可复现**：任何人按 README/文档的一条命令能得到相同结果。
2. **可验证**：有自动化测试或明确的验收命令，且本次真的跑过。
3. **可回滚**：改动可单独撤销（提交粒度、迁移脚本有 down、配置有备份）。
4. **可追溯**：关键决策有记录（记忆文件 / ADR / commit message）。
5. **无残留**：没有临时文件、调试打印、注释掉的死代码、未关进程。

## 交付前检查表

| 项 | 检查方式 |
|---|---|
| 构建通过 | 跑 build |
| 测试通过 | 跑 test，贴出结果 |
| 类型检查 | 跑 typecheck / tsc --noEmit |
| Lint | 跑 lint |
| 文档同步 | 改动的接口/配置/命令是否更新文档 |
| 变更说明 | commit message 说清「做了什么、为什么」 |
| 回滚方式 | 能否 revert 单个提交 |
| 残留清理 | `git status` 干净、无临时文件 |

## 分级

- **H（阻断）**：构建失败、测试红、安全漏洞、数据丢失风险。
- **M（应修）**：缺测试、文档过期、错误处理缺失。
- **L（可延后）**：命名、注释、格式。

H 未清零不得宣称完成。

## 与项目阶段的关系

- `active` 阶段：每片自测即可，不要求全量回归。
- `closing` 阶段：必须全量验证 + 文档同步 + 清理。
- 用户明确说「先这样/不用验证」时，按用户指令执行，但要在交付里写明「未验证」。
