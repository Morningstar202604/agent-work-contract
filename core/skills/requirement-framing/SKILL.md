# 需求框定（动手前的第一步）

## 五问

1. **真实目标**：用户说的和用户要的是一回事吗？去掉「手段」，留下「结果」。
2. **成功判据**：怎么判断做完了？可观察、可执行、可复现。
3. **范围边界**：必须改什么、明确不改什么、可以顺手做什么。
4. **约束**：技术栈、既有约定、性能/安全/兼容要求、时间与不可逆操作。
5. **未知与假设**：缺哪些信息？每条按最合理默认值补全并标注为「假设」。

## 输出模板

```markdown
【问题框定】
- 目标：<一句话，可验收>
- 成功判据：<命令/可观察结果>
- 范围：改 <...>；不改 <...>
- 约束：<...>
- 假设：<逐条，标注为假设>
- 风险：<高/中/低 + 原因>
```

## 规则

- 目标与手段分开：用户说「用 Redis」，先问要解决的是缓存、锁还是队列。
- 不擅自扩大范围，也不擅自缩小。
- 假设必须显式写出来，执行后仍可被用户纠正。
- 判断不了方向时按 AGENTS.md「五方案对比 → 自选最优 → 直接执行」，不阻塞。

## 与后续步骤的衔接

框定完成 → `task-slicing` 拆片 → `writing-plans` 或直接开工 → 每片验证 → `delivery-quality-bar` 收口。
