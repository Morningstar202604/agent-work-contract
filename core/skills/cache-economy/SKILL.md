# 上下文与缓存经济

目标：在同等结果下，让模型每一轮读取的 token 更少、命中缓存的比例更高。

## 底层事实

- 提示缓存按**前缀**匹配：前缀越稳定、越长，命中越多。
- 会话中途改变系统提示、工具集合、技能清单，会让缓存从改动点开始失效。
- 因此：**能在会话开始前定好的东西，不要中途改。**

## 六条纪律

1. **稳定前缀**：`AGENTS.md`、技能、子代理、工具集合属于前缀，会话中不要增删。装完新技能要重启会话才生效，不要边聊边装。
2. **只读一次**：同一文件一次会话内读一次，后续引用行号。改完再读是最常见浪费——除非改动可能破坏上下文。
3. **增量编辑**：用精确替换而不是整文件重写；重写会让 diff 与缓存全部失效。
4. **按需拉取**：先看目录/标题索引，再读命中的小节。不要「为了保险」把整个仓库读一遍。
5. **输出摘要**：工具输出只保留结论与关键行；不要把整份日志、整份测试输出塞进上下文。
6. **切片推进**：一片做完、验证、落盘记忆，再开下一片。上下文超长时用记忆文件做外存。

## 反模式

| 反模式 | 代价 | 替代 |
|---|---|---|
| 每轮重读同一批文件 | 重复 token + 缓存全失效 | 记行号，必要时只读 diff |
| 全量重写文件 | 后续轮次上下文全变 | Edit 精确替换 |
| 边做边装技能/改配置 | 前缀变化，缓存清零 | 集中一次改完，重启会话 |
| 把日志全文贴回 | 上下文爆炸 | 只贴失败摘要与关键行 |
| 一个巨型 todo 列表 | 每次注入都带全量 | 分阶段，阶段内只保留活跃项 |

## 长任务做法

1. 阶段开始时把「目标 / 约束 / 已定决策 / 已验证事实」写进记忆文件。
2. 阶段内只保留当前切片的上下文。
3. 阶段结束把结论压缩进记忆文件，丢弃中间过程。
4. 新阶段从记忆文件冷启动，而不是凭对话历史。

## 测量

- 观察每轮耗时与 token 使用；突然变慢通常意味着缓存失效或上下文膨胀。
- 一次会话里配置只改一次，改完重启。
