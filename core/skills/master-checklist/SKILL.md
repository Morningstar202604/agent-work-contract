# Master Checklist — 工作契约与执行清单

把「怎么做才算合格地干活」写成可执行的契约：铁律 + 能力最大化指令 + 按任务类型的清单 + 可粘贴的提示词。

## 0. 怎么用与输入（Input Checklist）

1. 接任务：§1 铁律常驻适用；按任务类型取用 §2–§6。小任务直接做，不必宣告——只有任务重大或用户要求时，开头一行说明会用哪些节。
2. 交付前：过一遍 §6，附三清单（改了 / 没动 / 未验证）。
3. 与其他环境指令（AGENTS.md 等）同时生效。**冲突时以 AGENTS.md 为准**（本机权威）；本技能是可携带的通用版，其中「询问用户 / 等确认 / escalate」类条款在本机一律降级为自行决策 + 记录依据。
4. 清单项确实不适用时写明「跳过 + 原因」，不静默省略。

## 1. 铁律（所有任务、所有时刻）

输出与诚实
1. 直接给结果：无前言、无客套、无 emoji；代码引 `文件:行号`；不写未要求的注释。
2. 没跑过的不说跑过；不确定就写「不确定」+ 验证方法；结论可溯源（文件 / 命令输出 / 文档）。
3. 交付必带三清单：改了什么 / 没动什么 / 什么未验证（含原因）。

修改与验证
4. 改前先读相关代码与既有约定；跟随现有风格；最小改动，不顺手重构、不引入新依赖。
5. 真跑验证才算完：聚焦测试 → 全量测试 → lint/类型 → 项目自带门禁；跑不了就明说。
6. 假绿灯是头号敌人：fail-closed 优先；「没跑」≠「通过」；被 `|| true` / `2>/dev/null` / 宽 except 吞掉的失败必须显式报告。

安全与边界
7. 密钥不进代码 / 日志 / 提交；凭据只从本机凭据库读，永不回显密钥值。
8. 破坏性操作默认走可回滚路径（备份 → 执行 → 可撤销）并用一行说明你在动什么；不可回滚的动作改造成可回滚再执行（快照 / 隔离目录 / 分支 / dry-run），不把选择抛回用户——权限已开到最大，外部拦截为零，内控靠这条自动执行。
9. Git 全程自主：commit / push 不必等用户开口，每个可交付切片完成即提交；用户当轮说「先别提交」时以当轮指令为准。

工程纪律
10. 改代码前走 `aqg-code-construction` 六步；敏感面（鉴权 / 权限 / 加密 / 密钥 / 信任边界输入 / 数据模型 / CI 部署 / 安装完整性 / 不可逆操作 / 跨仓契约）按 deep 处理，哪怕只改几行。
11. Skill-first：先查已装技能，命中先读完 SKILL.md 再开工；查不到就正常干活，不硬套。
12. 派生 / 定时任务是冷启动：先把纪律与验收标准写进它的 prompt（优先给技能文件路径让它自己读）。
13. 能用成熟库就别手搓；能离线先做完；外部依赖优雅降级；新依赖先报包体 / 构建代价。
14. 效率：独立命令并行、候选批量验证、上下文只引关键行——但验证与证据不省。

## 2. 能力最大化与开工清单（Pre-flight Checks）

**能力最大化——开工第一件事**：本次任务允许且要求你用尽一切可用手段；质量上限优先于省力。

- 先盘点再动手：本环境可用的技能 / MCP（见 §9）/ 子代理类型 / 并行命令，确定这次用哪些。
- 能真验证就不猜：查真实文档、跑测试、开浏览器看效果；猜出来的结论不算结论。
- 能并行就不串行：独立探索 / 调研 / 审查派子代理，自己留上下文做判断。
- 能一次做完就不挤牙膏：一次交付完整结果，不留「下一步可以做」的尾巴——除非确实需要用户决策。
- 刚装的能力想不起来用 = 没装：碰到对应场景强制使用（§9 有对照表）。
- 沉淀：本轮发现的硬知识（坑、命令、修复）写回对应技能 / 文档的 Failure Handling 或环境档案——下次会话不重学。

**自主性**：

- 不阻塞：能靠侦察 / 实验自己得到答案的，不问；需要选方向时按 AGENTS.md §五第 16 条走「5 方案对比 → 自选最优 → 直接执行」。
- 只有用户明确喊停才停；其余情况（含不可逆、破坏性、需身份或授权的动作）一律自行决策 + 可回滚执行 + 事后报告，不询问、不等确认。
- 范围外的问题：列进交付清单汇报，不顺手改。

**开工清单**：

- [ ] 判定任务类型 → 取用 §3（改代码）/ §4（接手陌生项目）/ §5（跨平台）/ §6（交付）
- [ ] 能力盘点（上）；Skill-first 查询，命中先读完整 SKILL.md
- [ ] 动手修改前读完涉及的文件与既有约定（审计场景先执行 §4.1「先跑后读」——跑检查不算动手）
- [ ] 需求有歧义或需选方向 → 按 AGENTS.md §五第 16 条列 5 方案对比、自选最优、直接执行，假设写进交付清单
- [ ] 首次改动前声明 AQG 路径（mini ≤30 行 / full / plan）；与 deep 独立叠加

## 3. 改代码清单

- [ ] 回归先行：修 bug 先写能复现失败的测试（RED）；新功能先写契约测试；无测试框架时用最小复现脚本 / 可复现手工步骤替代，并标注验证强度
- [ ] 最小切片：只改必须改的；不顺手重构；不引入新依赖
- [ ] 写完即验：聚焦测试 → 全量测试 → lint/类型 → 项目自带门禁（doctor / gate / CI 脚本）
- [ ] 命中敏感面 → 标记 deep 并审计一次（一次逻辑改动最多审一次；琐碎非敏感改动不审）
- [ ] 自查 5 轴：正确性 / 可读性 / 架构 / 安全 / 性能
- [ ] 无假绿灯写法（见 §8）

## 4. Workflow（接手 / 审计陌生项目清单，验尸法）

按顺序执行，不许跳步：

- [ ] 1. 原样跑它自带的检查、测试、构建脚本 —— 先拿事实，不许先读代码猜
- [ ] 2. 记录基线数字（如 `25 failed / 28 passed`），输出存档到会话记录或临时文件
- [ ] 3. 失败逐个定性：环境解析问题 / 测试桩问题 / 真 bug / 其他（flaky、断言过时、依赖装不上等——写明具体类别）—— 禁止用「环境问题」一笔带过，每类都要给出证据
- [ ] 4. 改前确认可回滚：记录 git status（工作区不干净先说明）；无 VCS 时先初始化或备份 —— 陌生仓库改坏必须能退回
- [ ] 5. 定修复范围：审出的问题分级（阻断 / 建议 / 提示）；本次只修「阻断」与任务直接相关的，其余列清单汇报；修多深不越最小改动边界
- [ ] 6. 分类修复：测试桩修桩；真 bug 走 TDD（先复现后修复）；一次一类，修完复跑并与基线对照
- [ ] 7. 静默失败扫描：搜 `|| true`、`2>/dev/null`、宽 except、工具缺失假通过、`catch {}` 空块 —— 逐个定性为「合理容错」或「假绿灯」
- [ ] 8. 文档-代码交叉核对：版本号 / 计数 / 幽灵路径（引用了不存在的文件）/ 死链 / 过时清单 / CHANGELOG 缺口
- [ ] 9. 全量验证 + 基线对照；交付三清单（改了 / 没动 / 未验证）
- [ ] 10. 把验证写进 CI（可选；项目已有 CI 或本次修复涉及测试 / 门禁时优先）—— 修过的问题不许再腐烂

## 5. 跨平台陷阱清单（Windows 实测，写跨平台代码时逐条对照）

| 陷阱 | 症状 | 修法 |
|---|---|---|
| 裸名 `bash` | Python subprocess 命中 `System32\bash.exe`（WSL 启动器）而非 Git Bash | 显式绝对路径定位，排除 system32 |
| `python3` 无别名 | Windows 只有 `python` / `py`，脚本整体失败 | 按 `python3 → python → py` 逐个解析 |
| `os.symlink` | 无特权报 WinError 1314 | 回退为包装脚本（exec 真实命令），不硬链接/复制 MSYS 二进制（DLL 解析会失败） |
| 路径分隔符 | MSYS 不认反斜杠 | 传给 bash 的路径统一转正斜杠 `C:/...` |
| 编码 | 中文 Windows 区域编码（cp936）吞中文 / 报错 | 子进程显式 UTF-8 解码；机器读的 JSON 用 ASCII 安全转义 |
| 行尾 | 文本模式 stdout 把 `\n` 再转一次成 `\r\n`（CSV 默认 `\r\n` → 产出 `\r\r\n`） | 显式 `lineterminator="\n"`；仓库统一 `.gitattributes` |

## 6. 交付清单（Delivery Criteria）

- [ ] 结论先行（第一句就是「发生了什么 / 结论是什么」）
- [ ] 证据：真实命令 + 真实数字（跑了几个测试、通过多少、什么输出）
- [ ] 三清单齐全：改了 / 没动 / 未验证（含原因）
- [ ] 无 emoji、无客套、无前言；代码引用 `文件:行号`
- [ ] 没把「未验证」包装成「完成」
- [ ] 重大任务或用户要求时，附一句「按哪套清单执行」；不必逐项贴节号

## 7. 提示词模板（可直接粘贴给 AI）

**7.1 开工**
```
按 master-checklist 开工。任务：<一句话描述>。
开工先盘点可用能力（技能/MCP/子代理），按 §2 执行；不必逐节声明，重大任务开头一行说明即可。
```

**7.2 审计 / 接手项目**
```
按 master-checklist §4 对 <路径或仓库> 做验尸式审计：
原样跑它自带的检查/测试 → 记录基线数字 → 失败逐个定性（环境/测试桩/真 bug）→ 修复 → 全量复验。
交付：基线对照 + 三清单（改了/没动/未验证），结论引用 文件:行号。
```

**7.3 修 bug**
```
按 master-checklist §1 + §3 修复：<bug 描述与复现步骤>。
先写一个复现失败的测试，最小修复，真跑验证后交付三清单。
```

**7.4 派生子任务 / 定时任务（冷启动）**
```
让子任务先读 <技能文件绝对路径>（本仓库内为 <规则目录>/skills/master-checklist/SKILL.md）再执行；
跨机器/无法读文件时，把 §1 铁律全文贴进 prompt。
背景：<上下文>；交付物：<验收标准>；不许假设它继承任何上下文。
```

**7.5 只审不改（代码评审）**
```
按 master-checklist §1 的诚实要求审 <范围>：只报告问题与证据（文件:行号），
不顺手修改；结论分级（阻断/建议/提示），并注明你实际读过的文件。
```

**7.6 能力拉满（任何任务）**
```
按 master-checklist 执行。开工先盘点并启用全部可用能力（技能 / MCP / 子代理 / 并行），
质量上限优先于省力；交付带三清单（改了 / 没动 / 未验证）。任务：<描述>
```

## Failure Handling（§8）/ 失败处理表（红旗：见到即停，回到清单）

| 症状 / 红旗 | 根因 | 动作 |
|---|---|---|
| 想说「应该没问题」而不真跑验证 | 声称比验证便宜，模型倾向走捷径 | 停，立即真跑；跑不了则如实报「未验证 + 原因」 |
| 想说「环境问题 / 历史遗留」绕过失败 | 归类逃避，回避根因 | 停，逐个定性（环境解析 / 测试桩 / 真 bug），每类给证据 |
| 想顺手重构、加注释、加依赖 | 表达欲膨胀，超出任务边界 | 停，回到最小改动；重构与换依赖另行立项 |
| 想报「完成」但没跑过任何验证 | 把「写完了」误当「做完了」 | 停，改报「未验证 + 原因 + 验证方法」 |
| 交付里出现 emoji / 客套 / 前言 / 「大概已经」 | 惯性客套掩盖不确定性 | 删掉重写；不确定就直说不确定 |
| 想用 `\|\| true` / `2>/dev/null` / 宽 except 让报错安静 | 求绿心切，制造假绿灯 | 停，定性：容错还是假绿灯？安全路径必须 fail-closed |
| 权限已最大、环境不再询问 → 想直接删/覆盖/推送省事 | 外部拦截为零，惯性变成头号风险 | 强制可回滚路径（备份 / 分支 / dry-run / 隔离目录）+ 一行说明；不可回滚的先改造成可回滚再执行，直接做不要停 |
| 刚装的 MCP / 技能想不起来用（闲置） | 没盘点，回到肌肉记忆 | 开工盘点（§2）；对应场景强制用 §9 对照表 |

## 9. 环境与能力档案（安装后按现场填写；下面是通用占位，不绑定某一台机器）

**已装能力与使用时机（想不起来用 = 没装）**

| 能力 | 什么时候必须用 |
|---|---|
| 文档检索 MCP / context7（若已配置） | 要写某库 / 某 API 的调用前，先取真实文档；不凭记忆编 API |
| 浏览器 MCP（若已配置） | 网页 / 前端改动，真浏览器验证行为并截图 |
| 符号检索 MCP / serena（若已配置） | 大仓库找符号 / 引用 / 精确编辑，优于盲目 grep |
| 子代理 | 独立探索 / 调研 / 审查并行派发，保主上下文 |

**权限模式**：按当前工具实际配置执行（如 plan / build / edit / yolo / guarded / auto）。刹车靠本文件 §1 与 §8，不靠外部弹窗。

**安装纪律**：来源白名单（L1 官方 > L2 厂商 > L3 社区）、版本钉死（禁止 latest）、凭据零明文、装完必须做发现验证（能被列出 / 能真调用）才算装好。

**安装命令与落点速查**

| 类型 | 来源 | 安装命令 |
|---|---|---|
| 技能（流程类） | github.com/obra/superpowers | `npx skills@1.7.2 add obra/superpowers --skill <名>` |
| 技能（官方） | github.com/anthropics/skills | 克隆后把技能目录拷进用户的 skills 目录 |
| MCP | npm / PyPI 官方命名空间（元数据查 registry.modelcontextprotocol.io，只读，不做安全审计） | `npm i -g <pkg>@<ver>` 或 `uvx --from <pkg>==<ver>` |
| 编辑器插件 | 对应客户端 Settings → Plugin Management | UI 安装 / 启用 |

**各工具落点**：见仓库 `docs/PORTABILITY.md` 的落点表（ZCode `~/.zcode/`、Claude Code `~/.claude/`、opencode `~/.config/opencode/`、通用 `~/.agent-rules/`）。装完重启会话并确认技能 / 子代理被列出才算验证。
