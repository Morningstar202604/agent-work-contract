# 任务拆解与切片

## 输入

- 用户原始请求（不要先润色成另一个需求）
- 现有代码/仓库状态
- 约束：技术栈、时间、不可改动的边界

## 拆解四步

1. **找主干**：这件事的最终可观察结果是什么？（能跑的命令、能看的页面、能读的报告）
2. **切纵向**：按「用户可见能力」切，不按「技术分层」切。
3. **定验收**：每片写 Given-When-Then 或一条可执行验证命令。
4. **排依赖**：标出「必须先做」与「可并行」，并行的分给子代理或分批执行。

## 每片的必备字段

```
切片名：
目标：一句话
改动面：文件/模块（预估）
验收：命令或可观察结果
依赖：无 / 依赖切片 N
风险：低/中/高 + 原因
```

## 粒度校准

- 一片应在一次会话内完成并验证。
- 如果一片需要改动超过 ~5 个文件或跨 2 个以上模块，继续拆。
- 如果一片无法独立验证，说明切错了方向（多半是横切而非纵切）。

## 输出格式

先给一张切片表（编号、目标、验收、依赖、风险），再给执行顺序。用户确认前不写实现代码——除非用户明确要求直接做。

## 与计划工具配合

- 切片表 → TodoWrite（每片一条，priority 按依赖与风险）
- TodoWrite 会自动同步到记忆文件「当前计划」
- 完成一片就更新状态，不要把十片都标 in_progress
